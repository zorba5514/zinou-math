# منصة الأستاذ زين الدين للرياضيات

**الرياضيات كما يجب أن تكون.**

منصة تعليمية لدروس الرياضيات من الأولى متوسط إلى الأولى ثانوي، مع دورات منفصلة. تضم حسابات الأولياء والأبناء، والاشتراكات، والدروس، والملفات، والاختبارات. هذا الملف يشرح كيف يعمل المشروع وكيف يُشغَّل ويُعدَّل.

## الحالة الحالية

| المرحلة | الحالة |
| --- | --- |
| 0. التجهيز | مكتملة |
| 1. الهوية والواجهة | مكتملة |
| 2. الحسابات وتسجيل الدخول | قيد المراجعة |
| 3 إلى 9 | لم تبدأ |

وثيقة المشروع الكاملة (المتطلبات، التصميم، خطة التنفيذ) موجودة في Claude Docs. ملخص القرارات التقنية في [docs/DECISIONS.md](docs/DECISIONS.md).

## كيف يعمل المشروع

- **الخادم:** `src/index.ts` يعمل على Cloudflare Workers. يوجّه كل طلب إلى صفحته، ويعالج طلبات البيانات `/api/*`.
- **الصفحات:** `src/pages.ts` يبني صفحات HTML في الخادم وترسل جاهزة، فتفتح بسرعة حتى على الهواتف الضعيفة. `src/html.ts` يهرّب كل نص تلقائيًا لمنع حقن الكود.
- **الحسابات:** `src/auth.ts` (الجلسات، والدخول، والقفل بعد 5 محاولات، والأجهزة المعتمدة)، و`src/auth-routes.ts` (صفحات الدخول والحساب والتأسيس)، و`src/admin-routes.ts` (لوحة التحكم).
- **التشفير:** `src/crypto.ts`: كلمات المرور بـ PBKDF2-SHA256 مع ملح عشوائي، والرمز ذو الأرقام الستة حسب المعيار RFC 6238. `src/qr.ts` يولّد رمز QR لربط تطبيق المصادقة.
- **قاعدة البيانات:** Cloudflare D1. الجداول في مجلد `migrations/`، وتُطبَّق آليًا عند النشر. الاختبارات تستعمل نفس الملفات على SQLite المدمجة في Node.
- **الفهرس:** `src/catalog.ts` يضم المستويات والدورات. محتواه **تجريبي مؤقت**، ويُستبدل بقاعدة البيانات في المرحلة 4.
- **الملفات الثابتة:** مجلد `public/`: التنسيق `styles.css`، والتفاعل `app.js`، وحسابات الرسم البياني `graph.js`، والشعار وأيقونات التطبيق في `brand/`، وترويسات الأمان في `_headers`.
- **التصميم:** يتبع مهارة zinou-design (خط Tajawal، بطاقات مستديرة، قائمة جانبية داكنة، والأصفر للعناصر المهمة فقط). الأيقونات في `src/icons.ts`.
- **الخطوط:** `npm run fonts` ينسخ خط Tajawal من حزمة Fontsource إلى `public/fonts/` قبل النشر. هذا المجلد لا يُحفظ في المستودع.
- **الإعدادات:** `wrangler.toml` يحدد اسم الموقع الحقيقي (`zinou-math`) واسم موقع الاختبار (`zinou-math-staging`).
- **الاختبارات:** مجلد `test/`، وتعمل بأداة الاختبار المدمجة في Node دون مكتبات إضافية.

## طريق كل تغيير

1. يُكتب التغيير في فرع مستقل، مثل `phase-0-setup`.
2. عند رفعه إلى GitHub، يشغّل الملف `.github/workflows/ci.yml` تلقائيًا:
   - فحص الأنواع والاختبارات الآلية.
   - فحص الأسرار (gitleaks): يرفض أي كلمة مرور أو مفتاح داخل الكود.
   - إنشاء قاعدة البيانات إن لم تكن موجودة، وتطبيق الجداول الجديدة.
   - النشر على موقع الاختبار، فقط إذا نجح ما سبق، ثم التحقق من أن الموقع وقاعدة البيانات يردان كما يجب.
   - فحص Lighthouse على الهاتف: يفشل إذا قلّ الأداء أو سهولة الاستعمال عن 90 من 100.
3. يجرّب الأستاذ التغيير على موقع الاختبار ويوافق عليه.
4. يُدمج الفرع في `main`. النشر على الموقع الحقيقي يُضاف عند شراء النطاق.

نتيجة كل تشغيل تظهر في تبويب **Actions** في المستودع، ورابط موقع الاختبار يظهر في ملخص التشغيل.

## الأسرار

لا توضع أي كلمة مرور أو مفتاح في الكود أبدًا. الأسرار محفوظة في GitHub: Settings ← Secrets and variables ← Actions.

| الاسم | الاستعمال |
| --- | --- |
| `CLOUDFLARE_API_TOKEN` | مفتاح النشر على Cloudflare. صلاحياته: Workers وD1 لحساب واحد. بدون تاريخ انتهاء، لذلك يجب حذفه واستبداله فورًا إذا شككت في تسرّبه. |
| `CLOUDFLARE_ACCOUNT_ID` | معرّف حساب Cloudflare. |
| `ADMIN_SETUP_CODE` | رمز التأسيس: يُستعمل مرة واحدة في صفحة `/setup` لإنشاء حساب الأستاذ. بعد إنشائه تُغلق الصفحة نهائيًا، فلا خطر من بقائه. |

إذا شككت أن المفتاح تسرّب: احذفه من Cloudflare (Manage account ← Account API tokens)، وأنشئ مفتاحًا جديدًا، وضعه مكان القديم في GitHub.

## حساب الأستاذ

- **الإنشاء:** مرة واحدة من صفحة `/setup`: رمز التأسيس، والاسم، ورقم الهاتف، وكلمة المرور، وربط تطبيق Google Authenticator بمسح رمز QR.
- **الدخول:** رقم الهاتف وكلمة المرور، ثم الرمز ذو الأرقام الستة من التطبيق على أي جهاز جديد. الجهاز الذي يُختار «تذكّره» لا يُطلب عليه الرمز سنة كاملة.
- **رموز الطوارئ:** 8 رموز تظهر مرة واحدة عند التأسيس. إذا ضاع الهاتف، يُكتب أحدها بدل الرمز. كل رمز يعمل مرة واحدة.
- **نسيان كلمة مرور الأستاذ:** غير متاح من المنصة حاليًا (حماية من انتحال الشخصية). يُعاد تعيينها من قاعدة البيانات بطلب من المطوّر.

## حسابات العائلات

- ينشئها الأستاذ من «إضافة عائلة»: اسم الولي، ورقم هاتفه (اسم المستخدم)، والأبناء ومستوياتهم.
- يولّد النظام كلمة مرور مؤقتة تظهر مرة واحدة، مع زر يفتح واتساب برسالة جاهزة. كلمة المرور المؤقتة لا تُحفظ إلا مشفّرة.
- عند أول دخول يُفرض على الولي اختيار كلمة مرور جديدة.
- 5 محاولات خاطئة متتالية تقفل الدخول 15 دقيقة. يستطيع الأستاذ رفع القفل فورًا من صفحة العائلة.
- إذا نسي الولي كلمة المرور: «كلمة مرور مؤقتة جديدة» من صفحة العائلة.

## التشغيل على حاسوب (للمطوّر)

يحتاج Node 22.18 أو أحدث.

```bash
npm install        # تثبيت الأدوات
npm run check      # فحص الأنواع والاختبارات
npm run dev        # تشغيل الموقع محليًا
```

للتجربة المحلية توضع الأسرار في ملف `.dev.vars`، وهو مستبعد من المستودع.
